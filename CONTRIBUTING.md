# Contributing

Open HomeView is built from folders. Each folder is one of:

| Kind         | Folder             | What it is                                                                |
| ------------ | ------------------ | ------------------------------------------------------------------------- |
| **App type** | `src/apps/<type>/` | A widget on the dashboard, a full-screen screen, or both (vacuum, lock…). |
| **Face**     | `src/faces/<id>/`  | A standby screen, with slots for small widgets (big-clock, modular…).     |
| **Theme**    | `src/themes/<id>/` | The look: colours, material, radius, font, shadows and motion.            |

A folder is found on its own; there is no list to update. The same folder can be
shared two ways:

- **In this repo:** open a pull request. It is reviewed and built into the image.
- **As a runtime pack:** build it into plain JS and CSS (`npm run build:addon`) and
  copy it into `/config/addons/` on a kiosk. No rebuild of the kiosk is needed.

See every built-in folder in the [gallery](docs/gallery.md).

## Development

```bash
npm install
cp .env.example .env.local   # add HA_TOKEN to test against the real Home Assistant
cp kiosk.example.yaml kiosk.yaml   # optional: your own config (git-ignored)
npm run dev                  # http://localhost:5173 — size the window to 1280×720
npm run test:unit
npm run lint                 # oxlint
npm run format               # oxfmt (Prettier-compatible output)
npm run build                # type-check + production build
npm run new app <type>       # a new app type (or: face <id>, theme <id>) from templates/
npm run build:addon <folder> # a runtime pack in dist-addon/
npm run build:site           # the project site and live demo in _site/ (site/, src/demo.ts)
npm run schema               # after changing the config schema or adding a folder
npm run gallery              # docs/gallery.md, after adding a folder or its preview.png
```

Without `HA_URL`/`HA_TOKEN` in `.env.local`, `npm run dev` runs against an in-memory **mock** built from `kiosk.yaml` (or the example). Add `?mock` to any URL to force the mock. In mock mode a small **Mock** toolbar (bottom-right) has a button for each of your `events` (fires it, like a doorbell ring) and one for standby. Keyboard: `E` = first event, `S` = standby.

## Structure

```text
kiosk.example.yaml        # example config: copy to kiosk.yaml
server/                   # Node server (runs .ts directly): serves the page, kiosk.yaml, layout.yaml and packs (kiosk.ts), and the HA auth proxy
scripts/                  # npm run new (new.ts), build:addon (build-addon.ts) and build:site (build-site.ts)
templates/                # what npm run new copies: a small app type, face and theme that work as they are
docs/gallery.md           # every folder's preview, generated by npm run gallery
site/                     # the project site on GitHub Pages (npm run build:site, .github/workflows/pages.yml) and the demo's kiosk.demo.yaml
src/
  addons.ts             # loads the runtime packs kiosk.yaml lists, before the rest (main.ts, then boot.ts)
  apps/                 # every app type, one folder each (see "App types" below)
  faces/                # every standby face, one folder each (see "Faces" below)
  themes/               # every theme, one folder each (see "Themes" below); ThemeHost puts the theme on <html>
  config/               # kiosk.yaml schema + validation (home.ts), shared schema helpers (fields.ts), loader, icons
  ha/                   # HaConnection interface, LiveConnection (home-assistant-js-websocket), mock
  kit/                  # what app, face and theme folders may use: AppSheet, Surface, Widget parts, FaceSlot, controls, useEntity/useService, defineAppType/defineFace/defineTheme (define.ts)
  stores/               # config (parsed kiosk.yaml), entities (HA state), kiosk (open app, overlay apps, standby)
  composables/          # useConfigReload, useIdle, useEvents, …
  components/
    atoms/              # IconButton, RangeSlider, ProgressBar, ToggleSwitch
    molecules/          # ClockDisplay, CameraFeed
    organisms/          # DashboardHost (the grid, and edit mode), WidgetCell, DefaultWidget, EditGallery, PinPad, StandbyHost (faces), DevToolbar, ConfigHelpDialog
  views/                # HomeView, ConfigErrorView
  styles/               # sizes and timings shared by every theme + base reset
```

Every component talks to Home Assistant only through `HaConnection` (`subscribeEntities`, `subscribeStatus`, `callService`). `LiveConnection` and the mock both implement it, and `src/ha/connection.ts` picks one.

## Start a folder

```bash
npm install
npm run new app garage-door     # or: npm run new face sunrise / npm run new theme ocean
```

This copies a small, commented template from [`templates/`](templates/) that works
as it is. Then:

1. Run `npm run schema` (kiosk.yaml's schema is built from the folders).
2. Use it in `kiosk.example.yaml` (tests render every type and face the example uses,
   and fail when one is missing), and look at it with `npm run dev`.
3. Add a `preview.png`: a screenshot of it (a widget at its default size, a face or
   a dashboard in your theme, about 480 px wide). A test fails without one. Then run
   `npm run gallery`.
4. `npm run type-check`, `npx vitest run`, `npm run lint` and `npx oxfmt` must pass.

## The rules

1. Import only from `@/kit`, `@/kit/define`, `vue`, `@lucide/vue` and your own folder.
   `npm run lint` checks it.
2. In `index.ts`, import `.vue` files only as lazy imports (`() => import('./X.vue')`).
   `status` may use `@/kit`, but no `.vue` files.
3. Talk to Home Assistant only with `useEntity` and `useService`, and only for entity
   IDs from your config. Pass IDs as getters (`useEntity(() => props.app.entities.x)`)
   so they follow prop changes.
4. Always provide `mock`, so `npm run dev` works without Home Assistant.
5. A widget must look right in every size it declares. Text follows the cell
   (`--u` inside `<Widget>`); use container units (`cqi`), not fixed pixels.
6. Colours come from theme tokens (listed in
   [`src/themes/glass/tokens.scss`](src/themes/glass/tokens.scss)). Only data colours
   (an app's or a scene's colours) may be literal, with a `// fixed colour: <why>`
   comment on the line above. A test checks it.
7. Themes change the look (colours, material, radius, font, shadows, motion), never
   the layout or sizes.
8. A theme with blur, canvas or WebGL ships a lite version without them
   (`lite.scss`). The kiosk runs on a Raspberry Pi.
9. One tap does one thing. Long-press is for quick controls (`widget.quick`) and the
   dashboard editor.
10. No network requests of your own.

Faces also: animate only `transform` and `opacity`, and use no timers but `useNow`
(once a second). Home data reaches a face only through the widgets in its slots.

## App types

Every folder in [`src/apps/`](src/apps/) is an app type, found on its own ([`src/apps/index.ts`](src/apps/index.ts)); the folder name is the type name. A type has a widget, a screen, or both:

```text
src/apps/vacuum/
  index.ts          # export default defineAppType(...): the kiosk.yaml keys (entity IDs +
                    # settings), the screen, the widget and fake entities for dev mode
  VacuumWidget.vue  # the dashboard widget, built from <Widget>, <WidgetIcon>, <WidgetLabel>…
  VacuumPanel.vue   # the screen, wrapped in <AppSheet> (full screen, ✕, icon, name, status)
```

- `widget: { widgetScreen, sizes, quick?, complication?, settings?, check?, variants? }`. `sizes` lists the cells it can take; the first is the default. A widget gets `app`, `size` and `mode` (plus `settings` if it declares any) and emits `open` to open the screen. Text sizes follow the cell height (`--u` inside `<Widget>`), so a widget looks the same in every size; the big value grows with the widget.
- `quick` is shown over the widget on a long-press (the brightness slider of `light` and `lights`).
- `settings` are keys of the widget itself on a dashboard entry (`group` on a Lights widget), checked like app keys; `check` cross-checks them against the app.
- `variants` lists one widget per part of the app, as `settings` (`app.groups.map((g) => ({ group: g.id }))` for Lights). The gallery offers each next to the app's own widget, and a dashboard made without `dashboard:` shows them instead of it. Any type with groups (rooms, floors…) gets this without touching the engine.
- A type without `widget` gets a 1×1 one from its `status` (icon, name, status text; tap opens the screen). A type without `screen` is widget-only (clock, scene…).

App folders import only from `@/kit` (UI), `@/kit/define` (`index.ts`), `vue`, `@lucide/vue` and their own folder; `npm run lint` enforces it. Talk to Home Assistant with `useEntity` and `useService`. The screen and widget are lazy imports (`screen: () => import('./VacuumPanel.vue')`), so the schema loads without the UI and each is its own chunk. A widget that throws shows as a grey "Widget error" cell; the rest of the dashboard keeps working.

```ts
// src/apps/garage-door/index.ts
import { type AppOf, defineAppType, entity, mockEntity } from '@/kit/define'

const definition = defineAppType({
  type: 'garage-door', // kiosk.yaml's `type:`, the folder's name
  description: 'A garage door: open, closed, and a button to move it.',
  icon: 'car',
  entities: { door: entity('cover') }, // flat on the app in kiosk.yaml
  screen: () => import('./GarageDoorPanel.vue'), // leave out for a widget-only type
  widget: {
    widgetScreen: () => import('./GarageDoorWidget.vue'),
    sizes: ['1x1', '2x1'], // the first is the default
    complication: true, // may sit in a face slot
  },
  mock: ({ name, entities }) => [mockEntity(entities.door, 'closed', { friendly_name: name })],
})

export default definition
export type GarageDoorApp = AppOf<typeof definition>
```

A widget gets `app`, `size` and `mode` (`dashboard` or `complication`), is built from
`<Widget>`, `<WidgetIcon>`, `<WidgetValue>` and `<WidgetLabel>`, and emits `open` to
open the screen. A screen gets `app` (and `focus`), wraps `<AppSheet>` and emits
`close`. See [`templates/app/`](templates/app/).

## Faces

Every folder in [`src/faces/`](src/faces/) is a standby face, found on its own ([`src/faces/index.ts`](src/faces/index.ts)); the folder name is the face id.

```text
src/faces/modular/
  index.ts          # export default defineFace({ id, name, description, screen, options, slots })
  ModularFace.vue   # the face: gets `options` and `night`, puts <FaceSlot name="right1" /> where widgets go
```

- `options` are the face's keys in `kiosk.yaml` (Zod fields with defaults, e.g. `color`); they can't be called `face` or `slots`.
- `slots` name the places for widgets and the sizes each takes (`right1: { sizes: ['1x1'] }`). `<FaceSlot>` renders the widget `kiosk.yaml` put there, in `complication` mode, or nothing. Only widgets whose type sets `complication: true` may sit in a slot.
- `StandbyHost` does the rest: the idle timer, swiping, tap to wake, night hours and the burn-in shift. A face only draws itself: no timers but `useNow` (once a second), and animate only `transform` and `opacity`.

Face folders follow the same import rule as app folders. To add one: `npm run new face <id>`.

```ts
// src/faces/sunrise/index.ts
import { defineFace, z } from '@/kit/define'

export default defineFace({
  id: 'sunrise', // kiosk.yaml's `face:`, the folder's name
  name: 'Sunrise',
  description: 'The time in one colour, with a widget under it.',
  screen: () => import('./SunriseFace.vue'), // gets `options` and `night`
  options: { color: z.string().default('#ff9f0a') }, // keys next to `face:`
  slots: { bottom: { sizes: ['2x1', '1x1'] } }, // <FaceSlot name="bottom" />
})
```

See [`templates/face/`](templates/face/).

## Themes

Every folder in [`src/themes/`](src/themes/) is a theme, found on its own ([`src/themes/index.ts`](src/themes/index.ts)); the folder name is the theme id.

```text
src/themes/liquid-glass/
  index.ts          # export default defineTheme({ id, name, description, modes, graphics })
  tokens.scss       # every theme token under [data-theme='liquid-glass'], other modes under [data-mode='light']
  lite.scss         # the lite version, under [data-graphics='lite']: only what is slow (blur, shadows, springy motion)
  material.scss     # optional: may style only .kit-surface, .kit-widget and .kit-sheet
```

- `modes` lists the modes `tokens.scss` styles; the first is the default. `graphics: ['full', 'lite']` means it ships a `lite.scss`. Without one, `graphics: lite` uses the full version and logs a warning.
- [`src/themes/glass/tokens.scss`](src/themes/glass/tokens.scss) lists every token, with comments; every theme sets all of them (a test checks it). Themes change colours, material, radius, font, shadows and motion curves, never layout or sizes.
- `ThemeHost` sets `data-theme`, `data-mode` and `data-graphics` on `<html>`, and `--tint` from `kiosk.yaml` (tokens use it as `var(--tint, <default>)`).

Theme folders follow the same import rule as app folders. To add one: `npm run new theme <id>`.

```ts
// src/themes/ocean/index.ts
import { defineTheme } from '@/kit/define'

export default defineTheme({
  id: 'ocean', // kiosk.yaml's `theme:`, the folder's name
  name: 'Ocean',
  description: 'Deep blue glass.',
  modes: ['dark'], // the modes tokens.scss styles; the first is the default
  graphics: ['full', 'lite'], // 'lite' needs a lite.scss
})
```

`tokens.scss` sets every token under `[data-theme='ocean']` (a test compares it with
glass's); `lite.scss` overrides only what is slow; an optional `material.scss` may
style only `.kit-surface`, `.kit-widget` and `.kit-sheet`. See
[`templates/theme/`](templates/theme/).

## Styling conventions

- Colours come from theme tokens (`var(--text-secondary)`, `var(--fill)`…), so every component works in every theme. A test fails on a literal colour outside `src/themes/`, unless the line above it says why with `// fixed colour: …` (a face's black background, text over a camera image, white on an app's own colours).
- `<style scoped lang="scss">` in every component.
- The root element and every important child get a class (`.light-card`, `> .name`, `> .status`) so parents can restyle children.
- Variants are props mapped to `-variant` classes (`variant="filled"` → `.-filled`). Props are used only for real variants, not one-off styling.
- No margin on a component's root; the parent handles layout with `gap`.
- No `!important`, and no inline styles except CSS custom properties for live data (brightness %, light color).
- Native attributes and listeners fall through to the root element. Slots with prop fallbacks (`<slot>{{ label }}</slot>`) keep components open for extension.

## Build a runtime pack

```bash
npm run build:addon src/apps/garage-door 1.0.0
```

This writes `dist-addon/garage-door/`:

```text
addon.json      # name, kind, version, kit (the kit major it was built for), description, files
index.js        # from index.ts
chunks/*.js     # the lazy screens and widgets
style.css       # component styles, or a theme's tokens
preview.png
```

`vue`, `zod` and the kit are not bundled: the kiosk provides its own copies, so a
pack shares its Vue and Home Assistant state. Icons from `@lucide/vue` are bundled
(only the ones you use).

To install it, copy the folder to `/config/addons/` next to `kiosk.yaml` and list it:

```yaml
addons: [garage-door]
```

Packs load in the built kiosk (Docker, or `npm run build`), not in `npm run dev`;
develop the folder in `src/` instead. A pack loads only on the kit major it was built
for (`KIT_VERSION` in [`src/kit/version.ts`](src/kit/version.ts)): rebuild it after a
kit major. A pack whose name is taken by a built-in folder, that was built for another
kit, or that fails to load is skipped, with a warning on the kiosk.yaml notice.

## Trust

A runtime pack is code you choose to run on your wall screen. It can't see the Home
Assistant token, and it can only reach the entities listed in `kiosk.yaml`. But it can
do anything else a web page can do, so only install packs you trust. The built
`index.js` is not minified, so you can read it first.
